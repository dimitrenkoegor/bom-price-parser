# bom-price-parser

Котировка BOM по электронным компонентам: на каждую позицию — **одно** предложение
авторизованного дистрибьютора через официальные API (DigiKey, Mouser, TME,
Newark/Farnell), итог — xlsx по эталону заказчика. Что API не нашли — `RFQ`.
Браузер не используется.

## Установка

```bash
pip install openpyxl          # единственная зависимость, Python 3.11+
copy .env.example .env        # и заполнить ключи
```

Для человека без консоли: `ЗАПУСТИТЬ.bat` (сам проверит Python и зависимости).
Рядом `ТОЛЬКО_РАСПОЗНАТЬ.bat` — только превью без цен, и `ПРОВЕРКА_одна_позиция.bat` —
одна тестовая позиция через API, чтобы убедиться, что ключи в `.env` работают.
Все `.bat` — однострочные обёртки над `_launcher.ps1`; русский текст держать только в нём
(UTF-8 с BOM). Кириллица внутри `.bat` ломает `cmd.exe`: на части Windows он исполняет
строки с середины (`'жет' is not recognized ...`).

## Запуск

```bash
python price_parser.py --input "start\запрос.xlsx" --output "final\результат.xlsx" --yes
python price_parser.py --once C5750X7R1H106KT 320 --manufacturer TDK --yes
python -m unittest discover tests
```

Без `--yes` скрипт остановится после превью распознанных позиций
(`превью_позиции.xlsx`): можно поправить артикулы и производителей в Excel и
нажать Enter.

Почтовый режим (письмо с BOM → ответ с ценами): `START_MAIL.bat`, описание —
`.agents/workflows/mail-monitor.md`.

## Документация

`AGENTS.md` — маршрутизатор «что нужно → какой файл открыть», он же инструкция для
ИИ-агента. Подробности — в `.agents/` (workflows, rules, references).

## Чем отличается от count pars

Соседний проект `Project C\count pars` показывает **все** предложения по каждой позиции
со всего спектра площадок (API, HTTP, браузер, брокеры с date code) — обзор рынка.
Этот выбирает одно предложение и работает только через API — котировщик. Общие у них
разбор артикулов (`src/bomprice/mpn.py`, `config/brands.toml`) и адаптеры API; эти файлы
держатся одинаковыми копированием.
