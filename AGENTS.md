# bom-price-parser — одна цена на позицию BOM через API дистрибьюторов

## Purpose

Вход: Excel-BOM (артикул, производитель, количество). Выход: итоговый xlsx по эталону
заказчика, где на каждую позицию выбрано **одно** предложение авторизованного
дистрибьютора либо стоит `RFQ`. Источник цен — только официальные API: DigiKey, Mouser,
TME, Newark/Farnell в основном проходе, oemsecrets/Nexar как добивка RFQ-остатка.

**Браузера в проекте нет.** Площадка без API — это `RFQ`, а не повод открывать сайт.
Обзор всех предложений по позиции со всего спектра площадок (включая браузерные и
брокеров с date code) — задача соседнего проекта `C:\Users\Huawei\Desktop\Project C\count pars`.

Код — пакет `src/bomprice/` (общее ядро с count pars + регламент отбора), точка входа —
`price_parser.py`. Этот файл — **маршрутизатор**: подробности лежат в целевых файлах,
читать их по одному и только по нужде.

## Команды

```bash
python price_parser.py --input "start\<запрос>.xlsx" --output "final\<результат>.xlsx" --yes
python price_parser.py --once <PN> <QTY> --manufacturer <бренд> --yes
python price_parser.py --preview-only                 # только распознать
python -m unittest discover tests                     # тесты
```

## Priority

При совпадении нескольких маршрутов побеждает верхний. Явная инструкция пользователя
перекрывает умолчания, но не Global constraints.

## Fallback

Ни один маршрут не подошёл — прочитать
[`.agents/workflows/api-search.md`](.agents/workflows/api-search.md) и уточнить у
пользователя. Не угадывать производителя и не подбирать аналог.

## Loading rule

## Изоляция задач

- Этот проект выполняет только выбор одного ценового предложения для каждой позиции BOM.
- Общая фраза `проверь`, `перепроверь` или `проверь ещё раз` не выбирает проект: она
  наследует рабочий корень текущего чата и запускает только локальную проверку последней явно
  обсуждавшейся задачи или артефакта этого чата.
- Если однозначного локального объекта в этом чате нет, уточнить его, не читая соседние проекты.
  Простая команда проверки ничего не исправляет и не публикует.
- Дополнительное действие выполнять только когда оно явно указано в той же команде (`исправь и
  проверь`, `проверь и публикуй`) и разрешено правилами текущего проекта; оно не разрешает смену
  проекта.
- Упоминание соседнего проекта является границей, а не маршрутизатором. Для чужой задачи
  вернуть `PROJECT_SCOPE_MISMATCH: bom-price-parser -> <проект-владелец>`, назвать владельца
  и остановиться до смены рабочей папки, чтения его файлов или вызова его навыка.
- Явно разрешённые общие навыки, утилиты и внешние источники данных остаются допустимыми;
  они не разрешают выполнять правила или создавать результаты соседнего проекта.

## Global constraints

1. `--yes` обязателен при запуске из-под агента: без него скрипт встаёт на `input()`.
2. Аналог с другими характеристиками недопустим. Отличаться может только суффикс упаковки
   (или маска `x` регламента).
3. Производитель не указан либо не совпал — это `RFQ`, а не подбор замены.
4. **Браузер, расширения браузера и парсинг сайтов не используются.** Нет API — `RFQ`.
5. Не регистрироваться, не вводить пароли и платёжные данные, не принимать соглашения.
6. Соседний проект `Project C\count pars` не изменять. Общие с ним файлы —
   `src/bomprice/mpn.py`, `config/brands.toml`, `tests/test_mpn.py`, адаптеры API —
   синхронизируются копированием: правка в одном проекте переносится во второй.
7. Не коммитить и не пушить без отдельной команды пользователя.
