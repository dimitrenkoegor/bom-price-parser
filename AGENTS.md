# BOM Price Parser — цены на ЭКБ по BOM

## Purpose

Автопоиск цен на электронные компоненты: письмо с BOM → парсер → API дистрибьюторов →
ответ письмом. Для каждой позиции выбирается **одно** предложение. Что не закрыли API —
`RFQ`. Браузер не используется: только официальные API и LLM-подсказка написания артикула
с обязательным подтверждением цены через API.

Это не обзор рынка: если нужны все предложения по каждой позиции сразу и date code —
задача соседнего проекта `..\count pars`, а не этого.

## Routing

| Сигналы в запросе | Читать |

| почта, автоответ, монитор не отвечает, `mail-state.json`, автозапуск | [`.agents/workflows/mail-monitor.md`](.agents/workflows/mail-monitor.md) |
| можно ли взять этот артикул, аналог, суффикс упаковки, маска `x`, производитель | [`.agents/rules/part-matching.md`](.agents/rules/part-matching.md) |
| какое предложение выбрать, MOQ, брекет, сток, Lead Time, когда это RFQ | [`.agents/rules/price-selection.md`](.agents/rules/price-selection.md) |
| колонки, стили, что значит персиковая строка, рубли | [`.agents/rules/output-format.md`](.agents/rules/output-format.md) |

Сквозной прогон: api-search → part-matching → price-selection → output-format.

## Изоляция задач

- Этот проект выполняет только выбор одного ценового предложения для каждой позиции BOM и
  собственный почтовый процесс.
- Общая фраза `проверь`, `перепроверь` или `проверь ещё раз` не выбирает проект: она
  наследует рабочий корень текущего чата и запускает только локальную проверку последней явно
  обсуждавшейся задачи или артефакта этого чата.
- Если однозначного локального объекта в этом чате нет, уточнить его, не читая соседние проекты.
  Простая команда проверки ничего не исправляет и не публикует.
- Дополнительное действие выполнять только когда оно явно указано в той же команде (`исправь и
  проверь`, `проверь и публикуй`) и разрешено правилами текущего проекта; оно не разрешает смену
  проекта.
- Упоминание соседнего проекта является границей, а не маршрутизатором. Для чужой задачи
  вернуть `PROJECT_SCOPE_MISMATCH: BOM -> <проект-владелец>`, назвать владельца и
  остановиться до смены рабочей папки, чтения его правил или вызова его навыка.
- Явно разрешённые общие навыки, утилиты, почта, площадки и внешние источники данных остаются
  допустимыми; они не разрешают выполнять правила или создавать результаты соседнего проекта.

## Global constraints

- `--yes` обязателен при запуске из-под агента: без него скрипт встаёт на `input()`.
- Итоговый xlsx руками не править: цена попадает в него только из прогона
  `price_parser.py`, где стоит проверка производителя и артикула.
- Аналог с другими характеристиками недопустим. Отличаться может только суффикс упаковки.
- Производитель не указан либо не совпал — это `RFQ`, а не подбор замены.
- Монитор почты запускать **одним** способом — руками либо автозапуском, не обоими: два
  экземпляра дерутся за почтовый ящик. `mail-state.json` не удалять, иначе клиентам уйдут
  повторные ответы.
- Соседний проект `..\count pars` не изменять.
