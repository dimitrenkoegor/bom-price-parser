# Почтовый контур

Полный цикл: письмо с BOM → парсер → API дистрибьюторов → ответ письмом.
Реализация — `mail_monitor.py`.

## Запуск и остановка

- Руками: `START_MAIL.bat` / `STOP_MAIL.bat`.
- Автозапуск: `INSTALL_AUTOSTART.bat` / `UNINSTALL_AUTOSTART.bat`.

**Запускать монитор одним способом — руками ИЛИ автозапуском.** Два экземпляра дерутся за
почтовый ящик.

## Состояние

- `mail-state.json` — отметки уже обработанных писем. **Не удалять**: иначе клиентам уйдут
  повторные ответы.
- `monitor.log`, `monitor.out.log`, `monitor.err.log` — журналы; `monitor.pid` — текущий
  процесс.
- `jobs_mail/` — рабочие задания контура.

## Поведение при RFQ-остатке

Флаг `HOLD_ON_RFQ` в `.env`:

- `false` — полный автомат, ответ уходит как есть;
- `true` — придержать ответ, пока в результате остаются RFQ-строки.

Придержанный остаток добирается каскадом — [`browser-cascade.md`](browser-cascade.md).

## Границы

Этот контур не перепроектировать в рамках задач по подбору цен. Правила подбора и формат
результата у него общие с остальными маршрутами и живут в `.agents/rules/`.
