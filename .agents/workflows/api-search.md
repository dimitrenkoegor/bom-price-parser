# Основной маршрут: поиск через API дистрибьюторов

Единственный маршрут поиска цен. Что API не закрыли — `RFQ` (остаток закрывается
ручным запросом поставщику вне этого проекта).

## Главная команда

```bash
python price_parser.py --input "<запрос.xlsx>" --output "final/<имя_результата>.xlsx" --yes
```

- `--input` — Excel-запрос (`.xlsx`/`.xlsm`) или `.txt` (строки `PARTNUMBER QTY [БРЕНД]`).
  Шапка и колонки распознаются сами: Условное обозначение / Наименование / Количество /
  Производитель. Строки без количества (примечания) пропускаются. `--sheet` — лист;
  несуществующий лист — ошибка со списком, лист не угадывается.
- `--header-row 3 --pn-col B --name-col C --qty-col E --mfr-col F` — ручная подсказка,
  когда шапка нестандартная (буквой или числом, A=1).
- `--output` — итоговый файл, по умолчанию `final/BOM_Приложение_1.xlsx`.
- `--yes` — **обязателен для агентов**: без него скрипт остановится на `input()` и зависнет.
- `--preview-only` — только превью; `--from-preview` — читать превью после правок человека;
  `--preview-path` — свой путь к превью (монитор кладёт его в папку задания).
- `--rub-rate 80 --rub-markup 4` — курс и наценка вручную (иначе ЦБ + `config/settings.toml`).
- `--limit N` — первые N позиций; `--no-cache` — не брать ответы площадок из `work/cache`.

Проверка одной позиции:

```bash
python price_parser.py --once <PN> <QTY> --manufacturer <бренд> --yes
```

## Что делает скрипт

1. Распознаёт позиции ([`../rules/part-matching.md`](../rules/part-matching.md), код
   `src/bomprice/bomread.py` + общий `mpn.py`) и пишет превью `превью_позиции.xlsx`:
   № · PN · Кол-во · Производитель · Исходное наименование · Уверенность · Замечания.
   Красный PN — не распознан, жёлтый производитель — пустой (уйдёт в RFQ). Без `--yes`
   ждёт правок и перечитывает превью.
2. По каждой позиции опрашивает франшизные API (DigiKey, Mouser, TME, Newark/Farnell)
   вариантами написания до первого попадания, затем повторно найденными точными
   артикулами (`src/bomprice/collect.py`). Позиции идут в 4 потока, к одному хосту — по
   одному запросу с его темпом.
3. Выбирает одно предложение по регламенту
   [`../rules/price-selection.md`](../rules/price-selection.md) (`src/bomprice/select.py`).
4. RFQ-остаток добивает агрегаторами (`oemsecrets`, в пределах суточной квоты, только
   авторизованные продавцы), затем LLM-контуром (если `ENABLE_CLAUDE_FALLBACK=true`:
   подсказка написания артикула → обязательное подтверждение ценой в API).
5. Пишет xlsx по [`../rules/output-format.md`](../rules/output-format.md) и печатает
   `Готово: <путь>` и `Найдено: N | RFQ: M` — эти строки парсит монитор, формат менять нельзя.

## Кэш и повторы

Ответы площадок лежат в `work/cache/<площадка>/<хэш>.json` сутки (`price_ttl_hours`):
повторный прогон того же запроса в сеть не ходит. Свежие цены — `--no-cache` или снести
`work/`. Суточные квоты (oemsecrets) — `work/quota.json`. Курсы — `work/fx.json`.

## Где лежат файлы

- `start/` — входные запросы; `final/` — результаты (в репозиторий не попадают).

Ключи, домены, зависимости, диагностика — [`../references/environment.md`](../references/environment.md).
