# Формат итогового файла

Эталон задаёт сам `price_parser.py`; ниже — контракт, который он реализует. При расхождении
описания и скрипта прав скрипт.

## Колонки

Ровно 10 колонок в этом порядке:

| Кол | Заголовок |
|---|---|
| A | Part Number |
| B | Distributor Part Number |
| C | Qty |
| D | Manufacturer |
| E | Distributor |
| F | Minimum Order |
| G | Stock |
| H | Lead Time |
| I | Unit Price USD |
| J | Unit Price RUB |

A и B стоят рядом намеренно — для визуального сравнения артикулов.
Колонка B заполняется только при отличии в суффиксе упаковки, правило — в
[`part-matching.md`](part-matching.md).

## Оформление

- Заголовок A, C–J: Arial 10 bold, белый текст, заливка `1F4E79`.
- Заголовок B: Arial 10 bold, белый текст, заливка `375623`.
- Строки с ценой: чередующаяся заливка `EBF3FB` / `FFFFFF`.
- Строки `RFQ`: заливка `FFF2CC`.
- Ячейки колонки B: заливка `E2EFDA`.
- Цена: числовой формат `#,##0.000`, если найдена; текст `RFQ` (bold, цвет `7F4B00`), если нет.
- Сноска: объединить A:J, Arial 9, цвет `595959`, перенос по словам.

## Происхождение строки видно по цвету

| Заливка | Что означает | Доверие |
|---|---|---|
| `FDE9D9` персиковый | `llm_assisted` — написание артикула предложил LLM-контур, цену подтвердил API | ниже обычного |
| `E4DFEC` сиреневый | `browser_assisted` — цена пришла из BOM-инструмента площадки через каскад | самое слабое, нужна выборочная проверка |

Обе категории считаются в сноске итогового xlsx **отдельно** друг от друга. LLM-контур
цену дать не может: он предлагает только написание артикула, строка заполняется лишь после
подтверждения через API.

## Рубли

`RUB = USD × (курс ЦБ + наценка)`. Наценка по умолчанию `+4`, курс берётся с `cbr.ru`.
Оба значения перекрываются флагами `--rub-rate` и `--rub-markup`.

## Куда пишется результат

Путь задаётся флагом `--output`, по умолчанию `final/BOM_Приложение_1.xlsx`.
Превью распознанных позиций — `превью_позиции.xlsx` в корне проекта.
